# Addarr Cloud Deployment with OpenTofu (GCP & Firebase)

This guide walks you through automatically deploying the entire cloud infrastructure for the **Addarr Telegram Mini App** using **OpenTofu** (or Terraform).

The deployment runs **100% within the Free Tier** (Firebase Spark / GCP Always Free) and is pre-configured for **European homelab operators** (`europe-west1`).

---

## Architecture Overview

```
+-------------------------------------------------------------------------+
| Telegram App / Mobile Client                                            |
|   Launches Mini App from Firebase Hosting CDN (europe-west1 edge)       |
+-------------------------------------------------------------------------+
                               |
                               | Realtime WebSocket Events
                               v
+-------------------------------------------------------------------------+
| Google Cloud / Firebase Realtime Database (europe-west1)                |
|   /requests/{userId}/{reqId}   <-- Client writes commands               |
|   /responses/{userId}/{reqId}  --> Client reads results                 |
+-------------------------------------------------------------------------+
                               ^
                               | Outbound Event Listener
                               | (Zero tunnels, zero port forwarding)
+-------------------------------------------------------------------------+
| Homelab Host (Local Network behind NAT)                                 |
|   Addarr Python Daemon                                                  |
|     - Uses serviceAccountKey.json generated by OpenTofu                 |
|     - Queries Sonarr (:8989), Radarr (:7878), Transmission, Sabnzbd     |
+-------------------------------------------------------------------------+
```

## 1. Prerequisites

Ensure you have the following installed on your management machine:

1. **OpenTofu** (v1.6+):

   ```bash
   # macOS
   brew install opentofu

   # Linux
   curl --proto '=https' --tlsv1.2 -fsSL https://get.opentofu.org/install-opentofu.sh -o install-opentofu.sh
   chmod +x install-opentofu.sh
   ./install-opentofu.sh --install-method deb
   rm install-opentofu.sh
   ```

2. **Google Cloud SDK (`gcloud`)**:

   ```bash
   brew install --cask google-cloud-sdk
   ```

3. **Node.js & npm** (v18 or higher):

   ```bash
   node --version  # should be >= 18
   ```

4. **Firebase CLI** (optional, recommended for initial login):

   ```bash
   npm install -g firebase-tools
   ```

## 2. Authentication & Setup

### Step 2.1: Create or Identify your GCP Project
Create a new project in the [Google Cloud Console](https://console.cloud.google.com/) or via `gcloud`:
```bash
gcloud projects create my-addarr-prod --name="Addarr Prod"
```
*(Note: Project IDs in GCP are globally unique across all Google Cloud accounts).*

### Step 2.2: Authenticate Google Cloud & Set Quota Project

> [!IMPORTANT]
> **Mandatory Quota Project Requirement:**
> The Firebase Realtime Database API (`firebasedatabase.googleapis.com`) strictly requires an active quota project when using Application Default Credentials (ADC). You **must** execute `gcloud auth application-default set-quota-project <your-actual-project-id>` or OpenTofu will encounter an `Error 403: The firebasedatabase.googleapis.com API requires a quota project`.

Authenticate your terminal session and configure the quota project:
```bash
# 1. Authenticate gcloud CLI
gcloud auth login

# 2. Set your active default project
gcloud config set project <your-actual-project-id>

# 3. Authenticate Application Default Credentials (used by OpenTofu)
gcloud auth application-default login

# 4. Set the quota project for ADC (REQUIRED for Firebase RTDB)
gcloud auth application-default set-quota-project <your-actual-project-id>
```

### Step 2.3: Log in to Firebase CLI
Log in so that frontend hosting and security rules deployment can publish to your Firebase project:
```bash
firebase login
```

## 3. Configure OpenTofu

Navigate to the `tofu/` directory:

```bash
cd tofu
```

Copy the example variables file:

```bash
cp terraform.tfvars.example terraform.tfvars
```

Edit `terraform.tfvars` with your project ID:

```hcl
project_id = "my-addarr-prod"

# Pinned to Europe (Belgium)
region        = "europe-west1"
rtdb_location = "europe-west1"

app_display_name   = "Addarr Telegram Mini App"
service_account_id = "addarr-homelab-bridge"
```

---

## 4. Deploy Infrastructure & Web App

Run OpenTofu initialization:

```bash
tofu init
```

Review the deployment plan:

```bash
tofu plan
```

Apply the deployment:

```bash
tofu apply
```

Type `yes` when prompted.

### What OpenTofu Does Automatically

1. Enables required GCP service APIs (`firebase`, `firebasedatabase`, `firebasehosting`).
2. Provisions the Firebase project and Realtime Database in Europe (`europe-west1`).
3. Applies database security rules from `firebase/database.rules.json`.
4. Creates the Addarr service account and exports `serviceAccountKey.json` directly to the project root with `0600` permissions.
5. Populates `webapp/.env.production` with live project credentials.
6. Builds the production web application (`npm run build`).
7. Releases the distribution bundle directly to Firebase Hosting.

---

## 5. Connect Your Homelab Addarr Instance

Once `tofu apply` completes, OpenTofu outputs your configuration snippet.

1. Open your Addarr `config.yaml` in the project root:

   ```yaml
   miniapp:
     enable: true
     url: "https://<your-project-id>.web.app"
     databaseURL: "https://<your-project-id>-default-rtdb.europe-west1.firebasedatabase.app"
     serviceAccountPath: "serviceAccountKey.json"
   ```

2. Start or restart Addarr:

   ```bash
   python src/addarr.py
   # Or with Docker:
   docker compose up -d --build
   ```

3. Verify log output:

   ```text
   INFO - Firebase Admin initialized successfully for Mini App bridge.
   INFO - Mini App bridge is actively listening for incoming requests.
   ```

## 6. Configure Telegram

Configure your bot so users can open the Mini App with one tap:

1. Open Telegram and search for [@BotFather](https://t.me/BotFather).
2. Send `/setmenubutton`.
3. Select your Addarr bot.
4. Send your live Hosting URL:
   `https://<your-project-id>.web.app`
5. Send the button label:
   `Open Addarr`

The bot chat now displays a persistent **"Open Addarr"** menu button.

## 7. Free Tier Guarantees & Cost Safety

This architecture is strictly designed to remain **$0/month**:

| Service | Free Tier Allowance | Addarr Usage Pattern |
| :--- | :--- | :--- |
| **Realtime Database** | 1 GB storage, 10 GB/month data transfer, 100 simultaneous connections | ~1 MB storage, ~50 MB/month transfer |
| **Firebase Hosting** | 10 GB storage, 360 MB/day data transfer, free SSL on `web.app` | ~250 KB app bundle, ~5 MB/day transfer |
| **Service Accounts & IAM** | Unlimited & Free | 1 service account |

> [!NOTE]
> Because Addarr performs user authorization locally in Python (`src/bridge.py`), no paid or always-on cloud compute (Cloud Functions/Cloud Run) is required. You can stay on the **Firebase Spark Plan** with zero commitment.

---

## 8. Teardown & Rollback

To destroy all cloud infrastructure:

```bash
cd tofu
tofu destroy
```

This tears down all GCP and Firebase resources cleanly without touching your local Sonarr, Radarr, or media library configurations.
